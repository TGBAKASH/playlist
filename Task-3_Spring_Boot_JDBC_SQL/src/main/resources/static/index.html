Bloom's Taxonomy K6

Microservices Architectural Patterns & Evaluation

Critical design decisions that differentiate this distributed system from monolithic architectures.

1. API Gateway & Reverse Proxy Pattern

Direct client-to-microservice calls introduce severe anti-patterns: CORS explosion, security perimeter leaks, and excessive roundtrips. The Spring Boot Gateway acts as a single ingress point, abstracting internal microservice topology.

✓ Benefit: Unified CORS, SSL Termination, & Client Abstraction

2. Database-per-Service Pattern

Catalog Service and Interaction Service maintain completely decoupled data boundaries. This eliminates table lock contention and prevents monolithic schema dependency, allowing polyglot persistence across services.

✓ Benefit: Zero cross-service schema lock & Independent Scaling

3. Circuit Breaker & Graceful Degradation

Implements Resilience4j fault tolerance. If interaction-service experiences network latency or crash, the Gateway trips to OPEN state, serving cached fallback catalog data without dropping the entire user session.

✓ Benefit: Eliminates Cascading System Failures

4. Docker Compose Multi-Container Orchestration

All 3 microservices and their dependencies are orchestrated using docker-compose.yml on an isolated bridge network (music-network). Internal service-to-service calls use automatic Docker DNS resolution.

✓ Benefit: Declarative Infrastructure & Zero-Configuration Networking
